==================================================
0. 製品の基本方針
==================================================

製品名：Slop Studio
対象OS：Windows 11（優先）、Debian GNU/Linux（将来の移植対象）
UIデザイン：Minimal CyberSquare
独自時間・ピッチ編集機能：Sloppy

■ 開発目的

一般的な制作操作を、
Windows上でも可能な限り同じ感覚で
利用できるDAWを開発する。

単に似た機能を搭載するだけでなく、
実際の制作ワークフローとの互換性を重視する。

ただし、以下は独自に制作する。

・アプリケーションのソースコード
・オーディオエンジン
・MIDI処理エンジン
・音源・エフェクト
・サウンドライブラリ
・アイコン
・画面の視覚表現
・プラグイン画面
・製品ブランド

■ 優先順位

1. 主要な制作ワークフローの互換性
2. ショートカットとマウス操作の互換性
3. 主要コマンドの機能的な配置
4. MIDI・オーディオ処理の正確性
5. Windows 11への適合
6. 独自のデザインと言語表記
7. 拡張性と保守性

名称変更だけを目的として操作を変更しない。

■ 操作互換性

・メニューの大分類を維持する。
・操作目的が同じ項目は近い位置に配置する。
・メニューの階層を不必要に深くしない。
・同じ結果を得るための操作回数を増やさない。
・マウス操作とショートカットは同じコマンドを実行する。
・一般的なDAW用語を積極的に使用する。
・他社固有の機能名には独自名称を使用する。
・他社の具体的なUIデザインを複製しない。

9. 最終開発原則
==================================================

Slop Studioは、
既存DAWを使い慣れたユーザーが、
Windows上で近い制作体験を得ることを目指す。

■ 維持するもの

・操作習慣
・編集ワークフロー
・機能的なメニュー配置
・ショートカットの考え方
・トラック管理
・MIDI編集
・ミキシング操作
・ウインドウ管理
・スクリーンセット

■ 独自化するもの

・ブランド
・ソースコード
・音声処理エンジン
・視覚デザイン
・アイコン
・音源
・プリセット
・サウンドライブラリ
・機能固有の名称

■ 最終方針

操作互換性のために必要な要素を、
理由なく削除しない。

独自ブランド化のためだけに、
使い慣れた操作方法を変更しない。

一方で、他社の創作的な表現や
権利保護された素材は無断利用しない。

独立した製品として、
操作性・品質・権利処理の
それぞれを検証しながら開発する。

10. Codexへの引き継ぎ規則
==================================================

■ 開発作業の最初に行うこと

1. リポジトリを調査し、既存の言語、ビルドシステム、GUI、音声処理を確認する。
2. 既存実装があれば壊さず、現在の状態をREADMEにまとめる。
3. 仕様項目を機能IDと優先度、依存関係に分解し、実装計画を作る。
4. 未確認の前提は「仮定」と明記し、勝手に実装済みとしない。
5. 自分でテストできる小さな単位で実装、動作検証、コミットする。
6. 依存ライブラリを追加するときはライセンス、ビルド要件、サイズを記録する。
7. 大規模なコード自動生成やファイル削除はユーザー承認を得る。

■ Codexが行ってはいけないこと

・メニューだけ表示する空実装を完成扱いしない。
・プロジェクトを開く／保存が動いていないのに完成と報告しない。
・音声コールバックでUI処理、ファイルI/O、ネットワーク通信を行わない。
・ライセンスや権利関係を確認せず、他社素材をリポジトリへ追加しない。
・第三者固有の音源、ループ、プリセット、ロゴ、アイコンを無許諾で流用しない。
・AIツールに権限の全面付与や無確認の削除権限を与えない。
・存在しないAPI、動作しないコマンド、見せかけの音声波形を偽装しない。
・Git履歴を消すような強制リセットを無断で行わない。

■ 提出・報告書式

・実装した機能IDと変更ファイル
・ビルド方法、必要な依存関係
・テスト結果とログ
・既知の制限、未実装機能
・次の1ステップ

12. オーディオエンジンとMIDIの非交渉要件
==================================================

■ リアルタイム処理

・内部音声処理は原則32-bit float、ステレオ以上と任意多チャンネルをサポート。
・44.1kHz、48kHzを最低限確認。96kHzは追加テスト対象。
・バッファ長は端末サポートに応じて選択（例：64～1024 frames）。
・再生、録音、オーバーダブ、ループ、停止、定位、ゲインを実装。
・オーディオコールバックで動的メモリ割り当て、例外送出、同期ファイルI/Oをしない。
・RTコールバックにロック待機、ネットワーク通信、AI推論、スクリプト実行、GUI更新を入れない。
・UIやAIからのコマンドは有界キューを介してオーディオエンジンに受け渡す。
・デバイス切断やサンプルレート変更を検知し、復帰方法を通知する。
・オーバーラン／アンダーランの検出とログを持つ。
・システム音量と出力バスの扱いを明示し、暴走する音量はリミッターで防止可能にする。

■ 時間モデル

・64-bit sample-frameを内部の絶対時刻として保持。
・テンポマップと拍子変更を持ち、表示の小節/拍/tickと相互変換。
・MIDI編集のPPQはプロジェクト定数で定義（初期案：960 PPQ）。
・サンプル、拍、フレーム表示の端数は丸め規則を統一する。
・録音時に遅延補正とイベントタイムスタンプを保持。
・サイクル／ループの継ぎ目に不要なクリック音を発生させない。

■ オーディオグラフ

入力 -> トラック -> インサート -> センド/バス -> マスター -> 出力
・モノ／ステレオ／任意チャンネルを明示。
・バスグループ化、ミュート、ソロ、パン、フェーダーに対応。
・音声ルーティングに循環がある場合は検出し、危険な接続を拒否する。
・プラグイン遅延補正（PDC）は段階実装し、未実装時は制限を表示。
・ピーク／RMSメーターとクリッピング表示を備える。
・録音音声は一時ファイルに逐次書込後、確定してプロジェクトに関連付ける。

■ MIDI

・Note On/Off、Velocity、CC、Pitch Bend、Program Changeを最初に実装。
・複数MIDI入力・出力、チャンネル、タイムスタンプに対応。
・オールノートオフとオールサウンドオフを区別して処理。
・録音中のMIDIイベントは失わないようにバッファを管理。
・MPE／MIDI 2.0は対応APIとプラグインの実態を確認して段階導入。

■ パニック！（すべての音を強制停止）

・ユーザーが操作すると、可能な全トラックのノートを直ちに停止する。
・内部音源の発音ボイスを解放し、プラグインへ適切な停止操作を送る。
・外部MIDIには必要に応じてCC120（All Sound Off）/CC123（All Notes Off）を送出。
・再生停止や録音中断が必要な場合は状態を安全に遷移させる。
・クラッシュやデバイス故障で停止できない場合はユーザーへ通知する。
・MCP/Lua/OSCからのパニックは許可設定に従うが、ローカルUI操作は常時可能。

13. 保存形式・復元・移行
==================================================

■ 保存形式

・標準拡張子の仮称：.slopstudio（配布前に重複調査を実施）。
・プロジェクト保存形式は仕様公開可能なコンテナ構造を目指す。
・構成例：manifest.json、tracks.json、regions.json、routing.json、automation.json、assets/。
・全IDは一意。参照整合性をスキーマ検証する。
・内部絶対パスは避け、素材は相対参照とする。
・外部素材をリンクで参照する場合はパスとハッシュ／変更日時を保持する。
・プラグイン状態はプラグイン規約に則って保存・復元する。
・サンプルレート、拍子、テンポマップ、言語に依存しない設定を保存する。

■ 保存の安全性

・保存は一時ファイルへの書込 -> 検査 -> アトミック置換を基本とする。
・保存時に直前の有効なプロジェクトをバックアップする。
・アプリ停止／電源断時でも前回正常保存から復元できること。
・オートセーブはユーザー設定の間隔／保持世代を持つ。
・新しいスキーマで古いプロジェクトを開く際はマイグレーションを実施。
・未来のスキーマを開く際は無理に上書きしない。
・破損素材を検出したら代替パス検索ダイアログを表示する。

■ 最低限のテスト

・保存 -> 終了 -> 再起動 -> 編集内容が一致する。
・録音後すぐ保存して、オーディオファイルが欠損しない。
・参照素材を移動すると「見つからない素材」として検知する。
・バージョン移行中に失敗しても原本を残す。
・意図的なクラッシュ注入後、前回正常状態が復元できる。

14. メニューとCommand Registry
==================================================

■ メニューの実装原則

・画面表示のラベルはIDから引く。処理を日本語テキスト比較で判別しない。
・メニュー項目はcommand_id / label_key / shortcut / handler / can_executeを持つ。
・状態フラグ：enabled、checked、visible、implemented、requires_project、danger_level。
・動的項目：最近使ったファイル、履歴、プラグイン、スクリーンセットは実データを反映。
・複数UIから同じ処理へアクセスする場合は同一command_idを使用。
・Undo/RedoはCommandの副作用と逆操作を記録し、トランザクション境界を持つ。
・バウンスやインポートなどの長時間処理は進捗・中断・失敗復旧を示す。
・「サービス > ないよ！」は無効な静的項目として表示し、UI上の遊び心として扱う。
・全ショートカットはIME入力中・テキスト編集中・フォーカス状態を考慮する。
・右Alt（AltGr）と左Ctrl+Altの判別はキーボード配列によって扱いを切り替える。

■ コマンド状態

未着手 / 設計中 / 実装中 / テスト中 / 実装済み / 保留 / 対象外
「実装済み」は自動テストまたは再現可能な手動テストに合格した場合だけ使用。

■ Command例（概念スキーマ）

{
  "id": "track.group.create",
  "label_key": "menu.track.group.create",
  "default_shortcut": null,
  "enabled_if": "project_open && selected_tracks_count >= 1",
  "undoable": true,
  "implemented": false
}

コード化する際は仕様を正規化してメニューと実装を対応付ける。
文字列に「▶︎」があるだけで実行機能が存在すると解釈しない。

15. MCP AI連携マネージャー（必須追加）
==================================================

■ 正式配置（順序厳守）

ウインドウ
  Luaスクリプト
  OSC/VRChat連携
  MCP AI連携マネージャー
  ゲームコントローラーマネージャー
  パニック！（すべての音を強制停止）

■ 目的

Slop StudioをMCP経由で外部AIエージェント（例：Codex等）から制御できるようにする。
また、必要に応じてSlop Studio自身が外部MCPサービスに接続できるようにする。
前者＝MCPサーバーモード（優先実装）。後者＝MCPクライアントモード（将来拡張）。
MCPは接続プロトコルであり、AIモデル自体は標準搭載を意味しない。

■ MCP AI連携マネージャー画面

・サーバー：停止／起動／再起動、ローカル接続先、使用ポート、接続ログ
・接続中クライアント：名称、接続方式、認可状態、切断
・公開ツール一覧：名称、説明、パラメータ、利用可否、危険度
・公開リソース一覧：プロジェクト概要、トラック・リージョン構造（許可されたものだけ）
・許可設定：読み取り、編集、録音、書き出し、ファイルアクセス、ネットワーク
・承認待ち操作：差分、変更対象、必要な承認理由を明示
・監査履歴：日時、呼出元、引数概要、操作結果、ユーザー承認、取消結果
・認証情報：OS認証ストアに保持しUI上に平文表示しない
・テスト：接続確認、権限確認、ツールのサンプル実行（無害なものに限る）

■ 初期状態

・MCPサーバーは初期状態で停止（明示的に有効化した場合のみ起動）。
・最初はローカルPC上の限定通信のみ許可。リモート接続は初期無効。
・ユーザーが許可したプロジェクトのみ公開する。
・認証なしの公開ポートを外部ネットワークにバインドしない。
・全ツール初期設定は読み取りのみ。編集系は許可と必要に応じ承認が必要。
・サーバー終了時に接続を終了し、未完了操作を安全に中止する。

■ トランスポート

・STDIO：外部AIクライアントからアプリ／ヘルパープロセスを起動する方式。
・Streamable HTTP：公式仕様と認可要件に従い、明示設定のときのみ使用。
・対応プロトコルバージョンと機能を接続時にネゴシエートする。
・互換性のないメッセージは適切なエラーとして返す。
・MCPへの応答はバックグラウンドで処理し、音声処理をブロックしない。

■ MCP公開ツール例

slop.get_command_catalog

slop.run_script
slop.change_plugin_state

■ ツールの実装規則

・入力はJSON Schemaで厳密に検証。範囲外値、パス越え、巨大データを拒否。
・すべてのツールに一意な名前、説明、引数スキーマ、戻り値型を定義。
・失敗時は機械可読エラーと人間向け説明を返す。
・複数回実行すると結果が変わる操作は冪等性の扱いを明示する。
・編集系は必ずCommand Registryへ送ってUndo履歴に統合する。
・長時間操作は進行状況とキャンセル機能を用意する。
・バルク変更は事前検証と一括Undoに対応する。
・レート制限、タイムアウト、同時実行数の上限を設定する。
・外部から来たテキストを実行命令として信用しない。
・トークン、シークレット、ファイルの全文を監査ログに平文保存しない。
・マイク入力、録音開始、外部ファイル読取／転送は権限・承認を必要とする。
・UIに実行元の表示を行い、ユーザーは即時停止／接続解除できる。
・認可されていないクライアントのツール実行を拒否する。

■ リソースとプロンプト

・リソースは明示許可された内容だけ公開する。
・パスや個人ファイルを全走査しない。
・プロンプトテンプレートは今後の拡張。初期実装で無理に追加しない。
・MCPへの対応は現行公式仕様の適合テストを通してから表示する。

■ UIの承認例

「AIエージェントが『Drums』トラックを作成しようとしています」
対象：現在のプロジェクト
操作：新規オーディオトラック
権限：編集
[許可] [今回のみ許可] [拒否]

※ 承認のスキップは、ユーザーが指定した限定的な安全操作だけに許可。
※ データ削除や外部送信などの危険な処理は毎回確認する。

16. Luaスクリプト・OSC/VRChat・ゲームコントローラー
==================================================

■ Luaスクリプト

・メニュー「ウインドウ > Luaスクリプト」で専用マネージャーを開く。
・編集、実行、停止、ログ、利用可能API一覧、サンプルを備える。
・標準APIは project / track / region / midi / transport / command を提供する。
・Luaからの変更はCommand Registryを経由しUndoと整合する。
・ファイル、ネットワーク、プロセス実行は初期無効・権限が必要。
・無限ループ防止、CPU時間／メモリの制限を設ける。
・スクリプトを音声リアルタイムスレッドで実行しない。
・第三者スクリプトの署名・信頼度・権限を表示する。

■ OSC/VRChat連携

・OSCの送信先／受信先／ポートを明示する。
・VRChat用プリセットは任意。利用者がアドレスと値を確認して適用。
・任意のOSCメッセージをUIコマンドやMIDI CCへ安全にマッピングする。
・ネットワークアクセスは初期はローカルのみ。外部接続は明示許可。
・ループバック、送信頻度制限、接続断検出を実装する。
・サンプルレートや再生位置等の配信は選択式とし、情報を送信しないのが初期値。
・受信した文字列は信頼しない。スクリプト実行やファイル操作へ直結しない。

■ ゲームコントローラーマネージャー

・接続したゲームパッドの識別、ボタン、軸、デッドゾーン、キャリブレーションを表示。
・再生、停止、録音待機、トラック切替、ノブ、XY、フェーダーへマッピング。
・プロファイルの保存・読込と機器切断復帰をサポート。
・権限のない外部制御による録音・ファイル削除を禁止。
・GUI操作優先、ゲームパッドが切断されてもオーディオを停止しない。

17. Sloppy 時間・ピッチ編集
==================================================

■ 機能境界

・Sloppy時間編集：トランジェント、タイムストレッチ、テンポ追従、位相整合。
・Sloppyピッチ編集：音高検出、音符単位の編集、ピッチドリフト、ビブラート、フォルマント。
・解析はバックグラウンドで行い、編集結果は非破壊パラメータとして保存する。
・ソース素材は変更しない。元の波形に戻す操作を持つ。
・解析キャッシュは無効化・再計算でき、プロジェクトと分離して管理できる。
・品質モード（プレビュー／高品質書き出し）を用意する。
・未実装のアルゴリズムや期待精度は品質保証しない。
・音声処理ライブラリを使用する場合は権利台帳に記録する。

■ 楽曲制作のための受入テスト

・1拍のドラムアタックをテンポ変更しても位置が保たれる。
・持続音の音程を変更しても不要な途切れが生じない。
・元に戻す／やり直すが行える。
・録音素材そのものは変更されない。
・同じ入力と設定なら同じバウンス結果が得られる（誤差許容範囲を定義）。

18. 音源、エフェクト、プラグイン
==================================================

■ 初期搭載音源の最低限

・簡易シンセ（正弦波／ノコギリ波等、内部実装）
・ADSR、フィルタ、ゲイン、パン
・MIDIベロシティ、Note On/Off、ポリフォニー
・保存／復元可能なプリセット形式

■ エフェクトの導入順

・ゲイン、パン、メーター
・3バンドEQ、ディレイ、シンプルコンプレッサー
・リバーブ、リミッター、サチュレーション等は段階実装

■ VST3プラグインホスト

・公式SDK・仕様に従い、利用許諾を記録する。
・プラグインの検索と再スキャン、カテゴリ、パス、失敗ログを実装。
・プラグインの状態保存／読み込み、MIDI入力、パラメータ操作を検証。
・UIスレッドと音声スレッドの分離を徹底する。
・不正プラグインでアプリ全体が落ちる危険を評価し、段階的な分離を設計する。
・外部プラグインが見つからないプロジェクトは、データを壊さずプレースホルダー表示する。
・ライセンス条件に合致しないSDK、プラグイン、アセットを含めない。

19. 多言語、入力、アクセシビリティ
==================================================

■ 言語と配列の独立性

・UI言語：ja-JP、en-US、de-DE、ko-KR。
・キーボード配列：OS入力方式や物理スキャンコードに対応し、UI言語から独立。
・ショートカットプリセット：標準＋11種類の非公式「風」プリセット。
・AltGrを必要とする文字入力をショートカットとして奪わない。
・日本語IMEと韓国語IMEの変換中・候補表示中はグローバルキー操作を抑止する。
・ショートカット表示は実際に有効な物理配列に即して描画する。

■ 翻訳品質

・すべてのメニューに翻訳キー。未翻訳は英語へのフォールバック。
・「Slop Studio」「Sloppy」は固有名詞として維持。
・DAW共通用語は自然な訳語を使い、必要に応じ英語原語を併記。
・Read/Touch/Latch/Write/Trim/Relativeは業界の操作互換性優先で原語表示＋説明。
・文字切れ、アクセラレータ重複、レイアウト崩れを4言語でチェック。
・視覚の要素だけでなくキーボードフォーカスとスクリーンリーダー用ラベルを設ける。

21. 品質保証と受入テスト
==================================================

■ 自動テスト

・メニュー項目にcommand_idがあり重複しない。
・すべてのメニューは対応するhandlerが存在するか無効表示になっている。
・ja-JP/en-US/de-DE/ko-KRに欠落した翻訳キーがないか検査する。
・12操作スタイルと配列のキー競合を検査する。
・MIDIの録音、ノート編集、保存・復元、ピアノロール操作を検査する。
・再生/停止/録音/レンダリング/パニックを検査する。
・Undo/Redoの整合性と、複数コマンドをまとめた操作を検査する。
・プロジェクトのマイグレーションとバックアップを検査する。
・VST3ホストはSDKのテストプラグイン等、権利処理できたテスト対象で確認する。
・MCPの権限拒否、破壊的操作の承認、ツール入力検証、切断を検査する。
・MCP処理中に再生音が途切れないことを負荷テストする。
・Luaの無限ループ制限、OSCポート競合、コントローラー切断を検査する。

■ 音声回帰テスト

・1kHz正弦波のレベル、波形、周波数。
・バッファサイズを変更しても安定再生。
・ループでクリック音が発生しない条件を検証。
・複数トラックの和、バス経路、ステレオパンを検証。
・バウンス結果の長さとチャンネルを検証。
・録音開始／停止位置と再生位置の整合を検証。

■ 対話操作の受入テスト

A. 新規プロジェクト作成 -> MIDIトラック -> ノート入力 -> 再生。
B. オーディオトラック -> マイク入力を選択 -> 録音 -> 停止 -> 再生。
C. リージョン複製 -> 分割 -> トリム -> Undo -> Redo。
D. 2トラック選択 -> ミックスグループ作成 -> 親フェーダーで制御。
E. 番号キー1、2でスクリーンセット切替 -> 保存 -> 復元。
F. 4言語切替 -> 同じコマンドIDが動作。
G. OSCメッセージ受信 -> 許可済みの再生操作。
H. MCP起動 -> 読み取り接続 -> 無許可編集は拒否 -> 承認後にトラック作成。
I. Luaスクリプト -> 指定された安全なトラック名変更 -> Undo。
J. パニック -> 内部音源と外部MIDIの音が安全に止まる。

25. 最終開発原則
==================================================

Slop Studioは、Windowsで音楽制作を行うための独立したDAWである。
操作感の維持は製品目標であり、商標回避のためだけに操作体系を大幅に変更しない。
一方、創作的な画面表現・独自素材・ソースコードは適切な許諾なしに流用しない。
Codexは小さく動く試作を積み上げて完成を目指し、実装状態を正確に報告する。
